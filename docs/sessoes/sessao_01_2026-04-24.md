# Sessão 01 — 2026-04-24

## Contexto

Início do projeto de leitura de faturas de energia da Neoenergia Cosern.
O objetivo é construir um agente especialista em energia, treinado progressivamente
com dados reais de faturas e conhecimento do domínio elétrico.

## Decisões Tomadas

### Escopo Inicial
- Distribuidora: **Neoenergia Cosern** (Rio Grande do Norte)
- Tipo de fatura: PDF (formato digital enviado por e-mail ou baixado do portal)
- Dados prioritários na primeira versão:
  - Identificação da UC (unidade consumidora)
  - Consumo em kWh
  - Leituras anterior e atual
  - Valor total e tributos
  - Data de vencimento e referência

### Tecnologias Escolhidas

| Linguagem | Biblioteca     | Justificativa                                              |
|-----------|----------------|------------------------------------------------------------|
| Python    | pdfplumber     | Facilidade de integração com ML/LLM, extração de tabelas   |
| Java      | Apache PDFBox  | Uso enterprise, performance, integração com sistemas legados |

### Estrutura de Dados

A classe/dataclass `DadosFatura` foi desenhada para ser agnóstica à linguagem,
permitindo comparação direta entre as duas implementações.
Futuramente será serializada em JSON para alimentar o agente.

## Prompt Original do Usuário

> "Quero que você crie dois diretórios, um chamado Java e outro chamado Python.
> Quero reunir um comparativo entre leituras de faturas de energia. Com Python irá
> utilizar o pdfplumber e com Java utilizará o Apache PDFBox. O objetivo é criar
> duas aplicações que leiam faturas de energia da Neoenergia Cosern, isso irá se
> tratar de um estudo e treinamento de um agente. Então iremos criar um agente
> especialista em energia a medida que iremos produzir, quero que todos os meus
> prompts e conversas sejam documentados como conhecimento."
